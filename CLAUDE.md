# Project context (read first)

Multi-tenant, multi-workspace SaaS ("Cloudbase") — npm-workspaces monorepo. See README.md for run instructions.

- `packages/shared` — Zod schemas, roles, password rules, error codes. **Single source of truth** for API + UI validation. Never duplicate a rule in backend/frontend.
- `backend` — Express 5, Drizzle ORM, PostgreSQL, pg-boss. Layering: routes → services → repositories; wiring only in `services/api/container.js`.
  Services: `services/api` (HTTP), `services/worker` (email + cleanup jobs). Tests: `npm test` (integration, real Postgres, `.env.test`).
- `frontend` — Vite + React + Tailwind v4. Reusable UI kit in `src/components/ui`, bound form fields in `src/components/forms`; every form uses `useAppForm`. App shell = own sidebar implementation in `src/components/sidebar` (variants inset [default] | floating, icon-collapse, mobile drawer; no shadcn/Radix).
- Design reference: `setup-clone_2.html` (structure) and **Untitled UI** (look): Inter, Untitled's gray scale + brand purple as the default `untitled` tenant theme, 8px controls, semibold 14px buttons (36/40/44px), 4px brand focus ring, thin borders. Tokens live in `frontend/src/index.css` (`--gray-*`, `--line`, `--line-strong`, `--accent`…); never hard-code a hex in a component.

## Rules from the owner
- **No browser-native form controls, ever.** No `<select>`, `type=date/search/number/color/file`, `alert/confirm/prompt`, or native `<dialog>`: use `Select`, `DatePicker`, `Checkbox`, `Switch`, `SearchInput`, `Dialog`, `ConfirmDialog` from `components/ui` (and `SelectField`/`DateField` from `components/forms`). Need a control that doesn't exist yet? Build it in `components/ui` first, on `Popover` when it floats.
- Everything reusable (even button/checkbox/switch/input); SOLID; **zero code duplication**; remove deprecated code completely.
- Must scale to millions of users: indexed queries, keyset pagination, stateless services.
- Visual style: **no shadows anywhere** — separate surfaces with borders only (clear, premium look). Dark mode = pitch-black page + neutral near-black surfaces (#0a0a0b / #141416, grey borders — no blue/slate tint). The navigation is light by default (white panel on a gray-50 rail); dark navy (#00072D) exists only as the selectable `midnight` tenant theme.
- App shell is exactly one viewport tall: navigation + content area are fixed, **content scrolls inside the content area** (header pinned); it never grows with content.
- **Layout contract — default = icon rail + section panel (Untitled UI style):** an 80px rail (cloudbase mark = workspace switcher, one icon per `navigation.js` section, then Setup, search, panel toggle, avatar/account menu) and a 300px panel (section title, a Search field that opens ⌘K, Menu | Recent tabs, 44px rows with a "+" for pages that can create records, and expandable parents with a connector line). The rail is a rounded gray card (64px + 8px margin) sitting inside the sidebar surface; the panel is the flat sidebar itself. **Style** (Customize, all three layouts): *flat* (default) = navigation and page side by side, divided by a border, nothing floating; *inset* = navigation sits on a tinted surface (`--chrome`) and the page is a white rounded bordered card on it; *floating* = navigation and page are separate rounded bordered cards with a gap (hide the rail panel with ⌘B for the slim floating rail). The panel hides with ⌘B; pages outside any section (Setup has its own tree) show the rail only. The classic sidebar (`layout: sidebar`) and the top bar stay selectable in Customize; phones always use the drawer. Content area = pinned header (page icon + title on the left, page actions slot on the right) over a scrolling body.
  **Global search (⌘K / Ctrl K):** `GlobalSearch` + `GET /api/v1/search` — records of every object (permission and sharing aware), people, and for admins Setup pages, settings and Setup records; pages match instantly in the browser. Layout (built from Untitled UI parts, our own light code): search bar · underline Tabs (scope) · outlined count Tags ("Accounts 3") + a "Filters" menu (sort, clear) · result rows · Empty state (avatar row for People, file icon otherwise) · key-hint footer. Server groups are index-backed (migration 0007), time-boxed to 250 ms each and cached 8 s (invalidated on any data, rule, sharing or membership change). Anything searchable must stay permission-filtered.
  **Customization (owner only):** the account menu (avatar) has Theme (Light / Dark / System — personal, saved on the account) and, for the workspace owner, **Customize** — a floating sheet generated from `UI_OPTIONS` in `packages/shared/src/uiSettings.js` (layout rail | sidebar | top bar, style flat | inset | floating, navigation colour; plus the accent theme). Settings live in `workspaces.ui_settings` (database, every member sees them), validated by the same registry. Add an option = one registry entry (+ CSS for colours). `type: 'color'` options (`navHex`, `accentHex`) take any `#rrggbb` from the `ColorPicker` (`components/ui`, Untitled-style area + hue + hex + presets; no native colour input); `packages/shared/src/color.js` derives every accent/navigation token from that one colour (readable ink, light + dark) and the app injects it via `lib/customColors.js`. **Theme presets** (`UI_PRESETS` in the same file): the Colors section has a "Theme presets" row that opens a second, stacked `Sheet` (`level={1}`; Escape closes only the top sheet) with complete colour looks — one click patches `palette`/`navColor`/`navHex`/`accentHex`; add a look = one registry entry. Brand presets recolour navigation + accent; *whole-app palettes* (`packages/shared/src/palettes.js`: Claude, GitHub, Linear, Notion, Vercel, Nord …) restyle page, cards, borders and text in light AND dark (eight surface colours per mode, everything else derived; `data-palette` + injected CSS) — add a palette = one entry there. A palette's dark mode is its own (e.g. Claude's warm charcoal); the default stays pitch-black neutral. There is no theme toggle in the content header.
  **Top bar layout (desktop; chosen in Customize):** same Flat | Inset | Floating styles — cloudbase mark = workspace switcher · every `navigation.js` item (groups are dropdowns) · account menu (search stays on ⌘K); items that don't fit go into a "More" menu (`OverflowList`). Phones always use the drawer. Don't build navigation-specific code twice: both layouts read `navigation.js` and share the workspace/account menus.
  Add a page by (1) adding its route in `App.jsx` and (2) one entry in `frontend/src/layouts/navigation.js` — sidebar, search and header pick it up automatically. Page header buttons: render `<PageHeaderActions>…</PageHeaderActions>` from the page. All icons come from `components/ui/Icon.jsx` — one set, **Untitled UI Icons** (`@untitledui/icons`, line style; add one by importing it there and naming it). `size-4` in rows, `size-5` on the rail and in panel rows.
  Rows are shared by the rail panel and the classic sidebar (`layouts/NavRows.jsx`, never duplicate them): 44px, 22px icon, 15px medium label, optional "+" (pages with `create: true` open the New dialog via `?new=1`), parents (`parent: { label, icon }` in `navigation.js`) expand with a connector line, plus the Search field that opens ⌘K. The classic sidebar is 264px: workspace switcher + collapse button, Search, rows grouped under small headings, Setup, user row with "…" menu; collapsing it leaves the rail. Measured spacing (do not drift): Content card: 48px header (`px-4`), body `px-4 pt-5 pb-4`, full width (pages that need a narrow form set their own `max-w-*`, left-aligned). Controls: 8px radius, buttons `rounded-(--radius-btn)` (pills only inside `.auth-scope`).
- **Tenant theming:** each workspace has a `theme` (untitled default, graphite, indigo, emerald, rose, midnight) set by admins (`PATCH /workspaces/:id/theme`) and applied to all members via `html[data-tenant-theme]`. Light/dark is separate and personal (`html[data-theme]`). Add a theme = entry in `TENANT_THEMES` (shared) + two token blocks in `frontend/src/index.css`.
- Git: work on `dev`, merge to `main` via PR. Commits authored as the owner (error0x0000001), no AI attribution lines.
