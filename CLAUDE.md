# Project context (read first)

Multi-tenant, multi-workspace SaaS ("Cloudbase") — npm-workspaces monorepo. See README.md for run instructions.

- `packages/shared` — Zod schemas, roles, password rules, error codes. **Single source of truth** for API + UI validation. Never duplicate a rule in backend/frontend.
- `backend` — Express 5, Drizzle ORM, PostgreSQL, pg-boss. Layering: routes → services → repositories; wiring only in `services/api/container.js`.
  Services: `services/api` (HTTP), `services/worker` (email + cleanup jobs). Tests: `npm test` (integration, real Postgres, `.env.test`).
- `frontend` — Vite + React + Tailwind v4. Reusable UI kit in `src/components/ui`, bound form fields in `src/components/forms`; every form uses `useAppForm`. App shell = own sidebar implementation in `src/components/sidebar` (variants inset [default] | floating, icon-collapse, mobile drawer; no shadcn/Radix).
- Design reference: `setup-clone_2.html` (structure) and **Untitled UI** (look): Inter, Untitled's gray scale + brand purple as the default `untitled` tenant theme, 8px controls, semibold 14px buttons (36/40/44px), 4px brand focus ring, thin borders. Tokens live in `frontend/src/index.css` (`--gray-*`, `--line`, `--line-strong`, `--accent`…); never hard-code a hex in a component.

## Rules from the owner
- **Reference Untitled UI before building ANY UI.** Find the matching component on untitledui.com (index https://www.untitledui.com/react/components: Base components, Application UI such as Drawers / Messaging / Sidebar navigations / Modals / Empty states / Featured icons / Avatars / Badges) and render it with `node tools/untitled-ref/shot.cjs <group>/<name>` (e.g. `drawers/user-profile-menu`) to see the real look and markup; then build ours to match, in our own light code. Never design from memory. Untitled is **colourful** (tinted featured icons, gradient cover banners, coloured badges/tags, photo avatars with presence dots) — nothing should look grey and plain.
- **No content-area header, ever.** The page body starts at the top of the content card: no 48px bar with an icon + title (the sidebar already says where you are). A page that needs actions/filters renders its own inline toolbar (`PageToolbar`). Phones keep only a bare menu button (drawer trigger).
- **Secondary navigation lives in the sidebar, not in an extra column.** A list or tree that exists only to navigate (the chat inbox, Documents' My Drive / Shared / Recent / Starred / Trash, a future section's tree) renders **inside the sidebar panel itself** (rail panel / classic sidebar). The page draws its own column for it only as a fallback when the navigation is not showing a panel (top bar layout, collapsed panel, phones). **Detail panels are different: the contact / group info (and any similar "details of what I'm looking at" panel) always opens on the right of the content, never inside the sidebar.**
- **Filters, sort orders and view switches are round, never boxes.** Use `RoundMenu` / `RoundButton` (`components/ui/RoundMenu.jsx`, Untitled UI's round icon buttons — a dot shows something is applied) and `Button shape="round"` for icon-only "add" buttons. No boxed `Select` or segmented box in a toolbar for filtering/sorting/layout. Every section panel in the sidebar has the same top row: a Search field + a round "+" (chat list, Documents); search terms live in the URL so the page and the sidebar agree.
- **Layout contract — default = icon rail + section panel (Untitled UI style):** an 80px rail (cloudbase mark = workspace switcher, one icon per `navigation.js` section, then Setup, search, panel toggle, avatar/account menu) and a 300px panel (section title, a Search field that opens ⌘K, Menu | Recent tabs, 44px rows with a "+" for pages that can create records, and expandable parents with a connector line). The rail is a rounded gray card (64px + 8px margin) sitting inside the sidebar surface; the panel is the flat sidebar itself. **Style** (Customize, all three layouts): *flat* (default) = navigation and page side by side, divided by a border, nothing floating; *inset* = navigation sits on a tinted surface (`--chrome`) and the page is a white rounded bordered card on it; *floating* = navigation and page are separate rounded bordered cards with a gap (hide the rail panel with ⌘B for the slim floating rail). The panel hides with ⌘B; pages outside any section show the rail only. Setup is a section with its own panel (Quick Find + the Setup tree, `layouts/SetupPanel.jsx`), like Chat and Documents. The classic sidebar (`layout: sidebar`) and the top bar stay selectable in Customize; phones always use the drawer. Content area = the scrolling body only, starting at the very top of the card (no header bar; see the owner rule above).
  **Global search (⌘K / Ctrl K):** `GlobalSearch` + `GET /api/v1/search` — records of every object (permission and sharing aware), people, and for admins Setup pages, settings and Setup records; pages match instantly in the browser. Layout (built from Untitled UI parts, our own light code): search bar · underline Tabs with full-colour icons (`ColorIcons.jsx`) — **All · Navigation** (pages + Setup pages, settings, configuration) **· Records** (CRM records + people) **· Documents** (admin; Setup records that are documents: email templates, letterheads, mail-merge/post/action-link templates, asset files) · chips with coloured icons and counts that narrow within the tab + round Filter and Sort buttons (menus) · result rows (coloured tile per object/kind, gradient avatar for people, coloured document icon per type — `lib/searchVisuals.js`) · Empty state (avatar row on Records, file icon otherwise) · key-hint footer. Server scopes: `all | records | people | navigation | documents` (groups `records, people, navigation, documents`). Server groups are index-backed (migration 0007), time-boxed to 250 ms each and cached 8 s (invalidated on any data, rule, sharing or membership change). Anything searchable must stay permission-filtered.
  **Customization (owner only):** the account menu (avatar) has Theme (Light / Dark / System — personal, saved on the account) and, for the workspace owner, **Customize** — a floating sheet generated from `UI_OPTIONS` in `packages/shared/src/uiSettings.js` (layout rail | sidebar | top bar, style flat | inset | floating, navigation colour; plus the accent theme). Settings live in `workspaces.ui_settings` (database, every member sees them), validated by the same registry. Add an option = one registry entry (+ CSS for colours). `type: 'color'` options (`navHex`, `accentHex`) take any `#rrggbb` from the `ColorPicker` (`components/ui`, Untitled-style area + hue + hex + presets; no native colour input); `packages/shared/src/color.js` derives every accent/navigation token from that one colour (readable ink, light + dark) and the app injects it via `lib/customColors.js`. **Theme presets** (`UI_PRESETS` in the same file): the Colors section has a "Theme presets" row that opens a second, stacked `Sheet` (`level={1}`; Escape closes only the top sheet) with complete colour looks — one click patches `palette`/`navColor`/`navHex`/`accentHex`; add a look = one registry entry. Brand presets recolour navigation + accent; *whole-app palettes* (`packages/shared/src/palettes.js`: Claude, GitHub, Linear, Notion, Vercel, Nord …) restyle page, cards, borders and text in light AND dark (eight surface colours per mode, everything else derived; `data-palette` + injected CSS) — add a palette = one entry there. A palette's dark mode is its own (e.g. Claude's warm charcoal); the default stays pitch-black neutral. There is no theme toggle in the content area.
  **Top bar layout (desktop; chosen in Customize):** same Flat | Inset | Floating styles — cloudbase mark = workspace switcher · every `navigation.js` item (groups are dropdowns) · account menu (search stays on ⌘K); items that don't fit go into a "More" menu (`OverflowList`). Phones always use the drawer. Don't build navigation-specific code twice: both layouts read `navigation.js` and share the workspace/account menus.
  Add a page by (1) adding its route in `App.jsx` and (2) one entry in `frontend/src/layouts/navigation.js` — sidebar and search pick it up automatically. A section with its own panel content (chat list, Documents views) is a `navigation.js` group with `panel: '<key>'` + one entry in `layouts/sectionPanels.js`; pages hide their own navigation column with `useNavPanel()`. **Any page made of side columns uses `PaneGroup` / `Pane` (`components/ui/Panes.jsx`) and sets `panes: true` in `navigation.js`**: flat/inset = columns divided by thin borders inside the page card; floating = every column (list, conversation, info, Documents views/files, Setup tree/page) is its own rounded bordered card with a gap, like the navigation. Never hand-roll `border-r` columns. Page actions/filters: render an inline `<PageToolbar meta=…>…</PageToolbar>` (or put them in the page's existing filter row) — never a header bar. All icons come from `components/ui/Icon.jsx` — one set, **Untitled UI Icons** (`@untitledui/icons`, line style; add one by importing it there and naming it). `size-4` in rows, `size-5` on the rail and in panel rows.
  Rows are shared by the rail panel and the classic sidebar (`layouts/NavRows.jsx`, never duplicate them): 44px, 22px icon, 15px medium label, optional "+" (pages with `create: true` open the New dialog via `?new=1`), parents (`parent: { label, icon }` in `navigation.js`) expand with a connector line, plus the Search field that opens ⌘K. The classic sidebar is 264px: workspace switcher + collapse button, Search, rows grouped under small headings, Setup, user row with "…" menu; collapsing it leaves the rail. Measured spacing (do not drift): Content card: body `px-4 pt-5 pb-4`, full width (pages that need a narrow form set their own `max-w-*`, left-aligned). Controls: 8px radius, buttons `rounded-(--radius-btn)` (pills only inside `.auth-scope`).
- **Tenant theming:** each workspace has a `theme` (untitled default, graphite, indigo, emerald, rose, midnight) set by admins (`PATCH /workspaces/:id/theme`) and applied to all members via `html[data-tenant-theme]`. Light/dark is separate and personal (`html[data-theme]`). Add a theme = entry in `TENANT_THEMES` (shared) + two token blocks in `frontend/src/index.css`.
- Git: work on `dev`, merge to `main` via PR. Commits authored as the owner (error0x0000001), no AI attribution lines.

## Documents (Drive), Chat, Meet
Design and phases: `docs/workspace-suite-plan.md`. **Documents is built** (`/app/documents`, `modules/drive`, `routes/drive.routes.js`, `pages/documents/`): per-folder access control (viewer | editor | manager) inherited down the tree until a Restricted folder, so people only ever see folders they are allowed into; every record's attachments live in `Records / <Object> / <record uuid>` and follow the **record's own permission** (never the folder grants); files are streamed to a `StorageDriver` (`shared/storage`, local now, S3-compatible next) with a size cap and checksum; previews use short-lived signed links; search over files and folders is ACL-filtered. Never read a drive file or list a folder without going through `DriveService` (it is the only place access is decided). The browser's file chooser is opened only through `useFilePicker` (`components/ui/FilePicker.jsx`). Chat and Meet are designed, not built (they need a realtime tier and an SFU — see the plan).

## Chat (and calls) — one module, not two
`/app/chat` (`modules/chat`, `routes/chat.routes.js`, `pages/chat/`, WebSocket tier `modules/chat/hub.js` at `/api/v1/realtime`). **Meet is a feature of Chat**: a call starts from a conversation, in-call chat is that conversation, one membership model. Messages are HASH-partitioned by `conversation_id` (PK `(conversation_id, id)`, client UUIDv7 ids = idempotent sends); read state is a per-member cursor (never per-message rows); realtime = Redis pub/sub per conversation with ref-counted subscriptions (`bus.js`), presence = TTL keys polled by the client; search = Postgres FTS on a generated `tsv` column scoped to your conversations; legal hold blocks edit/delete. Authorisation is one rule: be an active member (`ChatService.member`). Attachments are Drive files in `Chat / <conversation>` (`kind: 'chat'`, `record_object = '@chat'`): `DriveService.roleOn` decides by conversation membership **before** the admin shortcut — workspace admins must never read other people's chats through Documents. Profile photos and group icons: `PhotoStore` (`modules/users/photoStore.js`; JPEG only, signed immutable URLs from `shared/avatar.js`); show them with `<Avatar src={person.avatar}>`. Chat is a `navigation.js` group with `panel: 'chat'` — the rail panel / classic sidebar render the conversation list (`layouts/ChatPanel.jsx`, scoped with `.on-sidebar` so it uses navigation colours); `ChatPage` only draws its own list when the navigation does not (top bar, collapsed panel, phones). Link previews must only ever fetch public addresses (`LinkPreviewService`). "Add people" pickers use `components/ui/PeoplePicker` + `GET /api/v1/people`. Message UI follows Untitled UI's Messaging components (render them with `node tools/untitled-ref`-style captures of https://www.untitledui.com/react/components/messaging): avatar + name/time header, neutral bordered bubbles, reply quote with a brand rule, file cards, pictures with a name·size caption, the voice-note player (`VoiceNote.jsx`), reaction pills, typing bubble, and the textarea-style input (`Composer.jsx` + `UtilityButton`). Design, measurements and what is not built: `docs/workspace-suite-plan.md`. Calls use **LiveKit** (`CallService`, `shared/livekit.js`, `pages/chat/calls/`; owner develops on macOS: `npm run dev:livekit`, see `docs/calls-local-dev.md`) — rooms are conversation ids, tokens only for members, `room_finished` webhook closes crashed calls; `LIVEKIT_*` unset hides the call buttons.
